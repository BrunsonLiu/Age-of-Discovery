perf(start): 空屏 1.76 秒 → 0.78 秒 —— 主包到达前就用纯 CSS 画一屏

这轮换了问法：不再挤字节，而是问"**玩家第一眼看到什么**"。
新探针 test/e2e/probe-first-paint.mjs（FCP + #root 挂载时刻 + 开场卡 + 地图可看）。

slow4g 实测（400KB/s + 300ms RTT，cache 关闭）：
    FCP              1756ms   ← 也就是说前 1.76 秒只有一片深蓝底色
    #root 有子节点    1414ms
    开场卡            1414ms
    地图可看          4853ms
主包 199KB 要 1.27 秒才下完，React 挂上之前 `<div id="root">` 是空的。
那不是"慢"，是"看起来像坏了" —— 玩家第一件事就是判断这游戏有没有反应。

改法：在 index.html 的 #root 里放一屏**纯 CSS 启动屏**（罗盘玫瑰 + 英文副标题 + 细金线）。
它必须满足三条，否则就是"又一个拖慢首屏的东西"：
  · 样式**内联**在 index.html（引用 index.css 就等于要等 20KB 的 CSS 包）
  · **零外部资源**（不许 url(...)、不许用自托管中文字体 —— 那些正是要等的东西）
  · 动画只动 transform / opacity（合成器线程，主线程在解析主包时也照滑）
消失不需要任何 JS：`createRoot(...).render()` 会清空容器子节点（所以判据里也锁了
main.tsx 必须用 createRoot，换 hydrateRoot 就会把它留在 DOM 里）。

结果：**FCP 1756 → 780ms**（780 ≈ TTFB 300 + HTML 下载），第一帧就是完整的一屏。
地图可看 4853ms 基本不变（这一屏只有 1.3KB 内联 HTML，白送）。
另外确认开场卡出现时启动屏已经消失（同一帧实测 splash=false / intro=true）。

顺带做的两件事（都删掉了，没进仓库）：
  · probe-bundle.mjs 用 esbuild metafile 看主包构成：events.ts 161KB（文案库，随主包
    一起下，但它只在航行中才用）、react-dom 127KB、leaflet 在 MapView 分块里没进主包。
    events 想挪成懒加载会动到 resolveOutcome 的同步链（预览=实际那条），风险不对等，没动。
  · probe-block.mjs 复测时基线自己抖到 5971ms，所有候选都显示 −1.5s —— 说明这个探针
    **单次不够可靠**（首个 context 在冷浏览器里跑）。结论：它适合找数量级，不适合判
    0.2 秒级的差异；这类要改测 FCP/冷启动的重复测量。
