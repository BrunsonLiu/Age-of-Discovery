perf: 3D 板单帧三角形砍一半；进 3D 不再同步查着色器日志

用户要求"保留效果、减少卡顿"。先测再改：无头 Edge 是 swiftshader 软渲染，
fps 绝对值无意义，所以改用**跨机器可迁移**的四个数：帧时间分位、长任务、
CPU 采样自时间、以及 **GL 层单帧提交量**（直接 hook drawElements，
不用 renderer.info —— 它会累加两帧）。

找到两处纯粹白花的钱：

① 3D 板地形在投影。陆面 112,814 + 侧壁 118,494 = 231k 三角形，
   每一次阴影深度 pass 都要**再画一遍**：单帧 465k → 234k（-50%）。
   A/B 画面差：mean 1.02/255、仅 3.8% 像素变化 >4 级（地形是平的，影子几乎看不见）。
   所以改成 `castShadow = false; receiveShadow = true` ——
   港口建筑与船照旧投影（145 个投影体，单件都 <5000 三角形，代价可忽略）。

② three 默认 `checkShaderErrors = true`：每编译一个 program 都同步调
   getShaderInfoLog / getProgramInfoLog。甲板实测这两项 **~400ms**（getProgramInfoLog 351ms），
   全落在"点开 3D 那一下"。生产构建关掉，开发环境保留（GLSL 写错要行号）。

另外加了并行预编译（compileAsync），但**先判断 KHR_parallel_shader_compile**：
没有该扩展时 three 会退回同步 compile，101 个 program 一次编译完 ——
那是把"多次小顿"换成"一次长冻"，不做这个交换。

顺带澄清一个误判：2D 海图里没有任何 WebGL 在跑（`__map3d`/`__deckScene` 都是 undefined），
它的 JS 自时间 6 秒只有 27ms —— 屏幕上那点抖动是 swiftshader 合成，不是我们的代码。

【又一次假绿】性能预算第一次测到 0 三角形 / 0 call 却"通过"（`0 <= 300000` 恒真），
原因是前面的用例把渲染模式切走了。现在先强制 3D、并要求实测 >10 万才允许比较。

测试：单测 11227/0（+8 源码守卫）、map3d-check 91/0（+5 性能预算）、deck-view 123/0/1。
